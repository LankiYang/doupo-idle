# 焚炎异录 · 服务端权威与防作弊开发规范

> **规范性文档。新功能一律照此设计，不是参考资料。**
>
> 分工：本文讲「**架构上必须怎么防**」；[数值设计.md](数值设计.md) 讲「数字怎么定」；
> 部署根 `SPEC.md` 讲「接口契约与部署真相」（不在 git）。
> 三者冲突时：接口以 SPEC 为准，数值以数值设计为准，**架构红线以本文为准**。

---

## 0. 总纲

> **服务端是唯一权威。客户端只发「我是谁、我想做什么」，绝不发「结果是多少」。**

三条推论，越往后越容易被忽略：

1. 任何进入 **排行榜 / 存档 / 发奖 / 活动进度 / 成就** 的数字，服务端必须能**从权威档独立算出来**。
2. 算不出来 ⇒ **不发、不上榜、不计数**，并回一个**带 reason 的拒绝**。**宁可缺，不可假。**
3. 「防作弊」不是加一个校验函数，而是**这条链路从设计上就没有"信客户端"的分支**。

⚠️ 反面样板（**不要再照这个写**）：战力榜对「纯本地玩家」保留了一条兜底 —— 客户端报什么
`power` 就收什么。那是历史包袱，不是可以推广的模式。手气榜（v1.47）**刻意不做**这个兜底。

## 1. 四层防御（缺一层就等于没有）

| 层 | 拦什么 | 怎么做 | 本项目的样板 |
|---|---|---|---|
| ① **权威计算** | 改数字 | 服务端从权威档现算，body 不认任何结果类字段 | `POST /luck`（v1.47） |
| ② **上界截断** | 单笔爆量 | 令牌桶；或**截断在剩余量**而不是整条拒绝 | 世界 Boss 的 `damage`（单笔 4.5e6 / 回充 6e5 每秒 / 桶容量 4e7） |
| ③ **冷却限频** | 高频刷 | 按 playerId 冷却 + 按 IP 限频 | `SUBMIT_COOLDOWN` / `SAVE_COOLDOWN` / `IP_WINDOW` |
| ④ **结构不变量** | 时间线上自我矛盾 | 「A 与 B 必须同时成立」的关系写成 clamp，**迁移点与写入点各一处** | `shengCount ≤ pullCount` |

★ **只有 ③ 没有 ① 的"防作弊"，是限速的伪造。** 令牌桶拦得住"一秒打一万次"，
拦不住"一次报一个假数字"。四层要能**被单独指认出来**，说不清是哪一层在拦，就等于没有。

## 2. 硬性条款

### 2.1 写接口的 body 只认身份与意图

- body **只允许**出现：身份（`playerId` / 会话令牌）与**意图/参数**（`name`、`damage`、
  `op` + 参数、`playerId`）。
- **不允许**出现任何**结果类**字段：`power`、`avg`、`pullCount`、`shengCount`、
  进度、数量、奖励内容……
- 服务端**读都不读**这些字段。不是"读了再校验"，是**根本不读**。
- 对应的机器可验判据：客户端的提交体**键名恰好等于**白名单
  （`Object.keys(body).sort().join(',') === 'name,playerId'`）。多一个键就是"上报了数字"。

### 2.2 权威态的取法

- 一律走 `host.authoritativeOf(pid)`：**内存实例优先，否则直读 `saves/<pid>.json`**。
- **它是只读的。绝不 `acquire()`** —— 那会让一个挂机玩家被标记成在线，
  白烧 1Hz 的 tick CPU。**读权威档不该有副作用。**
- 取不到权威态 ⇒ `{ ok:false, reason:'noauth' }`，**不上榜 / 不发奖**。
  **不许降级成"那就信客户端报的"** —— 那是把 ① 层自己拆掉。
- ⚠️ `authoritativeOf` 读的是**原始存档**，**不跑 `migrate()`**。所以 clamp 不能只写在迁移里。

### 2.3 回执语义

- 业务性拒绝一律 **HTTP 200 + `{ ok:false, reason:'…' }`**，不是 4xx/5xx。
  —— 玩家的正常状态（冷却中、还没达标）不该在控制台留一片红字。
- 回执要带上**让界面能说人话**所需的字段。例：`nosheng` 拒绝带 `pullCount`/`shengCount`/`minSheng`
  ⇒ 界面能写「还差 1 张圣阶才能上榜（当前 0 张 / 46 抽）」，
  而不是一句冷冰冰的"未上榜"。
- ⚠️ **改了回执语义，要回头重读客户端每一条按旧语义写的早退/合并分支。**
  这类回归只有端到端脚本抓得到（v1.36 的 `justKilled` 就是这么漏的）。

### 2.4 不变量

- 「A 与 B 必须同时发生」的关系，**写在同一个位置的同一处代码**。
  例：`shengCount++` 与 `pitySheng = 0` 紧挨着 —— 放一起是刻意的，
  口径要对得上，「出圣阶」与「保底归零」在代码上就必须是同一件事。
- 每个不变量在**两处** clamp：
  1. `migrate()` —— 防老档、畸形档、字符串、负数、1e9；
  2. **写入点**（服务端路由）—— 防**伪造档**。
- 反例：`shengCount ≤ pullCount` 只写在 `migrate()` 里是**不够**的 ——
  推一份伪档进来就绕过了（`authoritativeOf` 不跑迁移）。
  在「越低越好」的榜上，**分母被灌水就是瞬间第一名**。

### 2.5 存档字段

- **能不加字段就不加**（红线①：存档防死档）。必须加时：
  - 走 `migrate()` 容错，**绝不因为多两个字段把老档判死**；
  - `migrate()` 用 `{ ...parsed, ... }` 展开，未知键必须能存活。
- **绝不碰 `storageKeys.ts`** —— 键名变了 = 全服进度清零。
- ⚠️ **分清"看着像计数器、其实不是"的字段**：
  - `pityTian/pityQuasi/pitySheng` —— 是「距上次出货多少抽」，**出货即归零**，不是终身计数；
  - `roster` —— 会去重，还会被分解/兑换**增删**，不是"抽到过几张"；
  - `gifts` 是时间戳表、`kills` 是击杀数；
  - `activities.total.*` 是真正的终身计数器，但**远程模式下 `bumpMetric` 被短路** ⇒ 覆盖不全。
  ⇒ 要一个**终身累计**口径，就**新增一个字段**，别从旧字段估算。
- **不做回溯**：存档里没有的历史，不许估算补播。估算的各人偏差方向不一致；
  需要两个数一起播才公平的场合，只播一个就是**系统性不公**。

### 2.6 幂等键

- 幂等键必须带**足够的区分度**：`wb2-p<期>-k<轮>-reward-<sha1(pid)[:12]>` 里的
  `wb2-` 前缀**不能省** —— 发放通道是**按 id 去重**的，同一天两只 Boss 撞 id
   ⇒ 奖励邮件**被静默丢掉**（不报错、只在"玩家没收到"时暴露）。
- 幂等键里加了一个维度（如轮次），要回头检查**所有**构造/清理这个键的地方
  （`zero` 命令没清 `kills` 就是第二个病灶）。

### 2.7 「复制一套」优先于「抽公共函数」

- **已验证过的代码路径不重构。** 新玩法 / 新榜单 **复制一套**，不把老的改成通用的。
  用重复换上线安全，这是**刻意的选择**。
- 复制块顶部写死注释：「这是 X 的副本，改那边时同步看这里」。
- 公共函数只抽**真正无状态**的：`validId` / `cleanName` / `readBody` / `send` / `resolveToken`。
- ⚠️ 副本不能被"改成多实例结构" —— 现有数据文件里有真实归档与正在跑的玩家数据，
  重写整族函数的风险与收益完全不成比例。

## 3. ★ 列举点清单（复制一套时必须逐个走到）

「复制一套」的失效点，**从来不在被复制的函数里，而在"把所有东西列一遍"的地方**。
每加一套东西，逐个问：

- [ ] **启动加载**（进程起来时把它读进内存了吗）
- [ ] **关停落盘**（`shutdown()` 的 flush 列表里有它吗）
- [ ] **定时清理**（60s 之类的 interval 里的过期表清了吗）
- [ ] **归档**（该进 history 的进了吗）
- [ ] **运维 CLI**（`bin/doupo-*` 认它吗）
- [ ] **健康检查 / 探活**（`/health` 或对账脚本数得到它吗）

★ 漏一个**不会报错**：`setImmediate` 排队的写会被 `process.exit(0)` 一起带走，
**少了不报错**，只在"刚好那一刻重启"时表现成少一笔数据。这类 bug 只有**列举点清单**能防。

## 4. 验证规范

每条都要求**该判据自己能失败**（否则是恒真的空话）：

- **「服务端算而不是客户端报」必须有一条负对照**：夹具构造权威档 `pullCount=200/shengCount=4`，
  请求 body **故意带 `avg:1.0, shengCount:9999`**，断言回执是 `100/3`。
- **门槛 / 过滤类判据必须带真负对照**：夹具里真的放一个不满足的样本（`shengCount = 0`），
  且断言它**不在**结果里；同时放一个满足的（`shengCount = 1`）断言它在。
- **排序类判据必须断言方向**（越低越前 / 越高越前），不能只断言「返回了 3 条」。
- **「零请求 / 计数为 0」必须配正对照**，否则是恒真的空话。
  例：「进这个页签时 `POST /luck` 次数必须是 0」——要同时证明它在**切过去之后会发**。
- **数值常量直读源码**，不复述第二份（分母改了，按比例构造的用例语义会悄悄变）。
- **夹具要断言「夹具生效」**：证明那个路径真的被打到了 / 那条 404 真的被观测到了。
- **判据要落在「要发的那份产物本身」上**：上线前拿**该产物**跑行为验证，
  而不是只验源码或构建日志。
- 配套：**沙盒 →（改了 UI/引擎则重建产物）老锚点回归 → 体验服真站点只读冒烟**
  → 正式服部署 → 部署后回读。

## 5. 部署纪律

- **顺序是硬要求：先重启后端、后切客户端 `index.html`。**
  反了 = 玩家点进一个**永远拉不到数据的空页**。部署脚本要把这条写成硬闸。
- 回滚点：`cp -r` 必须在**改动之前**，并**当场自证**两条 ——
  ① 与**此刻线上那份**逐字节相同（证"抓的就是现状"）；
  ② **不含即将发布的新代码**（证"cp 没晚一步"）。
  ⚠️ `cp` 晚一步 = 与现状逐字节相同、名字却叫 `before` 的**静默失效备份**，
  只在"真要回滚"那一刻才暴露。
- 先传 `assets/`、**最后切 `index.html`**、**绝不用 `--delete`**
  （线上 `assets/` 堆着历史入口 chunk，是缓存了旧 `index.html` 的玩家的兜底，删了 = 白屏）。
- 三处 md5 一致（构建源 / 文件系统 / `curl` 回读）+ 复验**旧入口仍 200**（回滚路真在）。
- 「内存态 + 定时落盘」的服务：**改数据文件前必须停服**（退出中的进程会把内存态 flush 回写）。
- ⚠️ 正式服与体验服**共用同一份 `server.js` / `engine.cjs`**（靠 `DOUPO_PORT` / `DOUPO_DATA_DIR` 切换）
  ⇒ **任何一次 `restart doupo-api` 都会把这些改动同时带上正式服**。
  所以服务端代码必须先过 `node --check` + 沙盒全套。
- 体检 / 对账类工具：**必须主动列出"它没看懂的东西"**，并且**拿不到基线要非零退出**，
  绝不降级成"只取样"（绿灯在骗人的成本远高于红一次）。

## 6. 已知缺口（**不许假装不存在**）

反作弊链条：① `/score` 权威化 ✅ → ② 灰度开关 ✅ → ③ **放量（未做）** → ④ **`/save` 收窄（等闸门）**。

⚠️ **`POST /save` 目前仍是权威** —— 推一份伪档上去，`/state` 就回那份。
也就是说「客户端改数据刷钱」**至今仍然通**。
⇒ **本规范第 2.1 条对"存档本身"暂时不成立**，这是有意的分期，不是已解决的问题。

在这条补上之前：

- 凡是**能换钱的量**（货币、资源、奖励），优先让服务端**从权威档现算**，
  而不是"从玩家报的存档里读"。
- ③ 的闸门应该是**「`POST /save` 的日请求掉到很低」**，而不是"铺开率到某个百分比"
  （build 哨兵对"更早就已在跑的老页面"永远无效 ⇒ 等不到 100%）。

**实战印证（2026-09-20）**：当天真的抓到了两个伪造存档的玩家，**改档手法与上面这条缺口完全对上** ——
两人都是直接在客户端改数据、推上云端，服务端照单全收（一个把装备词条的 `value` 单独改成天文数字、
另一个把整队角色伪造成"满级满星"）。**发现他们靠的不是这条规范，而是游戏自己的不变量**（见 §9）。
处置完了，但**缺口一条没少**：本轮只是针对性地给这两个 id 上了道锁，没有堵住 ④。

## 7. 新功能落地清单（照抄）

做任何**带数字、带榜、带奖、带进度**的新功能时，逐条走：

- [ ] 口径定义：这个数字**服务端能不能从权威档独立算出来**？算不出来就别做这个榜/奖。
- [ ] 需要新的**终身累计**量 ⇒ 新增存档字段（`freshState` + `migrate` + 累加点**与归零点同处**）。
- [ ] 需要新榜 / 新玩法 ⇒ **复制一套**，老路径一行不改。
- [ ] 写接口：body 白名单（只身份 + 参数）；读权威档用 `authoritativeOf`（**只读**）；
      取不到 ⇒ `reason:'noauth'`。
- [ ] 不变量在**迁移点 + 写入点**两处 clamp。
- [ ] 门槛类逻辑回 `200 + ok:false + reason`，并带够界面说话所需的字段。
- [ ] 过一遍 **§3 列举点清单**。
- [ ] 验证：负对照（假数字 / 不满足门槛的样本）+ 方向断言 + 「夹具生效」断言。
- [ ] 改了 UI/引擎 ⇒ **重建产物再跑老锚点回归**。
- [ ] 体验服先上 + 真站点**只读**冒烟 ⇒ 再走正式服那套部署纪律。
- [ ] 同步文档：本文第 8 节索引 / SPEC / 数值设计 / 项目记忆。

## 9. 实例：存档伪造的发现与处置（2026-09-20）

> 修的是一份**真实线上存档**，不是演练。**本节的 playerId 一律只给掩码**（前 4 + `…` + 后 2），
> 玩家名不写入本仓库。

### 9.1 发现：别去论证"多大算离谱"，去问引擎

榜面第一眼就不对 —— **#1 战力是 #3 的 1353 倍，而关卡只高 45 层**。但"看起来离谱"不构成判据。
真正能落地的办法是**让游戏自己验自己**：

`src/game/data.ts` 的 `rollAffix` / `rollReforgedAffix` 已经声明了一条不变量（也是坑 27 的由来）：

```
value === round((base + roll * span) * 品阶倍率, 1)      // 且 roll ≤ 1 + 洗练bonus（按品阶）
```

⇒ **每一条词条都能被引擎自己验一遍**，不需要人给阈值。再加上两条：

- `stars ≤ MAX_STARS`
- **全服对照面**：把没被点名的档聚起来当基线（实测：最高等级中位 5 / 最大 315，**满星角色 0 个**）

结果（`temp/census-save-integrity.cjs`，只读）：

| | #1（`e408…d1`） | #2（`2b63…94`） |
|---|---|---|
| 判据命中 | **9 条词条超模，最大 4032.3×** | **56 个角色呈二值分布**：19 个 `1级/0星` + **37 个 `2000级/50星`**，无中间值 |
| 关键细节 | **`roll` 是正常值、只有 `value` 被改** ⇒ 手工改档，不是掉落异常 | 正常档是同级别角色的**连续谱**（如 252/20★、171/20★）—— **二值分布本身就是判据** |

★ **对照面是判据的一部分**：没有"正常档长什么样"这一栏，上面两条都只是"我觉得大"。
★ **尺子宁松勿严**：第一版我按 `roll ≤ 1.0` 卡，把 4 份**正常**档判成"超模 1.2~1.3×" ——
洗练的上界是 `1 + bonus`（圣阶 **1.45**）。**红的往往是尺子，不是产品。**

### 9.2 处置：只删伪造量，保留真实进度

- 超模词条的 `value` **按它自己的 `roll` 重算回去**（装备本体 / `roll` / `type` 一律不动）
- 伪造的角色打回 `1级 / 0★ / xp 0` —— **还原基线取"该档内未被污染的角色状态"**，不是拍脑袋定的值
- 伪造的资源余额归零；**`highestStage`、塔进度、真实角色、正常装备一律保留**（清了就是误伤真人）
- 榜单按 playerId 精确删除；**绝不整文件覆盖**（先 `systemctl stop` → 改文件 → `start`）

### 9.3 ★ 清零必须配「回灌锁」，否则活不过一次页面刷新

`/save` 的"拒绝倒退"**只看 `highestStage`**，而清理时刻意保留了它（那是真实进度）
⇒ **对方原样上传旧档不会被拒** ⇒ 清零在分钟级被自己盖回去。

解法：`api/data/freeze.json` 给这两个 playerId 设 `floor = 999999`（任何上传都 `< 999999` ⇒ `reason:'frozen'`）。
**正对照可以零风险构造**：拿**当前已清理的那份档本身**原样 `POST /save` 当探针 ——
最坏情况也只是写回同一份内容。实测 `{"ok":false,"reason":"frozen"}` 且档 mtime 未变。

⚠️ 两条别踩：`frozen` **不是 4xx、客户端静默忽略**（"看起来一切正常、只是进度再也不上传了"）；
探针**必须走玩家真实路径** `/doupo/api/save`，直连 `:8787` 要写 `/save` —— 写成前者会得到
**404 `{"error":"not found"}`**，而这个 404 极像"服务端接受了写入"。

### 9.4 边界（**别写成"已经解决"**）

1. **清的是云端档与榜单**。灰度放量是 **0%（全员本地模式）** ⇒ 他们浏览器里的存档仍是作弊状态。
   `/score` 走服务端权威态 ⇒ **榜面确实干净了**，但要连本地一起清，只能走放量（阶段 ③，未批准）或封号。
2. **`freeze.json` 等于禁止这两人再上传存档** —— 这是 9.3 的必要代价，不是副作用之外的额外收获。
3. **`POST /save` 仍是权威**（§6）—— 本轮**没有改变**这一点。

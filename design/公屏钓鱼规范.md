# 公屏钓鱼规范（开发中）

## 范围与当前交付

目标是在现有挂机游戏之外增加多人共享的灵潭：可移动、占钓位、钓鱼，以及有限度的增益和干扰。钓场不是主线地图，也不改变战斗的 1Hz 服务端引擎。

当前交付是**单人试营业竖切**：可点击移动、选择钓位、抛竿、鱼讯、扬竿、控线、收获/脱钩，以及场景、男女角色、鱼和环境动画。鱼获只进入本标签页的临时鱼获背包与鱼券循环，不进入主游戏存档、云档、灵金、榜单或可交易经济；页面必须明确告知玩家。不能把这份本地状态当成实时房间或权威结算。

## 场景与动画

- 世界坐标以背景图原尺寸为准；岸线和钓位由 `src/game/fishingModel.ts` 定义。移动只发生在可走区域；跨岸路径经过下方步道，不可穿过水面。
- 背景是一张静态、可迁移的 WebP；水纹、浮漂和场景植被是独立层。装饰动画按本地时间运行，不向服务器同步帧号。
- Canvas 画布尺寸由 `ResizeObserver` 同步：只有 backing store 像素尺寸变化时才重置 `canvas.width/height`；尺寸重置后必须在同一次 observer 回调内立即重绘当前帧，不能把透明空画布交给浏览器合成。鱼讯提示、抛竿按钮等 HUD 变化不得造成可见闪屏。
- 鱼讯阶段点击钓场任意位置或按空格可扬竿；控线浮层应在窄屏保持紧凑，明确标出本次鱼的动态安全区、收鱼进度和按住/松手提示。安全区由鱼的难度锁定宽度、左右移动速度和起始相位：鱼越难，安全区越窄、移动越快；鱼竿的安全上限和等级可提供容错与宽度加成。张力处于动态安全区内才增长进度，区间外进度下降；越过安全区上界应提示松手，满进度才钓获。控线时点按池塘等同于按住收线，抬起、取消或失去指针捕获时释放，不要求玩家必须点击底部按钮。不得以视觉文案掩盖本地数据未接服务端的事实。
- 男女角色的南、北、东向分别参考造型生出八格步态；西向镜像东向。离线去白、清理杂点和按下半身对齐后成为四行八列图集；停步回到无竿站姿。侧向摆臂与跨步须目视验收，不因八格齐全就自动视为合格。五种鱼（灵鲤、银鳞鱼、赤纹鲈、墨金鲶、翠鳍鳊）各使用八帧定轴摆尾图集，沿水道往返并水平翻面。鱼种表和运动参数集中在 `src/game/fishingSpecies.ts`。
- 占位后使用**单独生图**的男女持竿姿势：侧向和背向各四格（持竿待机、后引、前抛、收线），西向镜像侧向。抛竿按顺序切姿势，等待回待机，收线/钓获用收线姿势。人物及鱼竿烘在同一透明帧里，Canvas 不绘制人物、竿身或悬空连线；浮漂、水纹、水花和较小鱼影属于独立场景反馈。降动态偏好仍保留离散动作姿势与交互提示。
- 美术资产需要在目标尺寸、手机和桌面各看至少两个循环。移动不能使用 `sprite-sheet.cjs` 的固定根系阈值作为合格判据；详见 `design/精灵图动画规范.md`。
- 降低动态效果时保留交互反馈，但停掉装饰摆动和水面漂浮。

## 试营业鱼获与渔具循环

参照《潜水员戴夫》的捕获、经营收益、升级装备的正反馈，以及《星露谷物语》的鱼种收集、鱼饵/钓具与品质差异，先做可检验的小循环：**占位与控线 → 鱼获入包 → 收藏/出售/兑换 → 升级渔具 → 调整下一竿概率和手感**。这不是对两款游戏机制或美术的复制。后续可增加图鉴、时段/天气鱼讯与合作事件，但必须先解决服务端权威结算和社交反滥用。

参考资料：《潜水员戴夫》发行方 [Steam 游戏介绍](https://store.steampowered.com/app/1868140/DAVE_THE_DIVER/) 明确描述捕获、餐厅经营与用收益升级装备；《星露谷物语》[1.6 官方更新日志](https://www.stardewvalley.net/stardew-valley-1-6-update-full-changelog/) 记录钓鱼节、专用鱼饵、加速上钩鱼饵、鱼获加工增值及新鱼种收集反馈。这里仅抽象其循环设计，不照搬数值。

- `src/game/fishingSpecies.ts` 是单一鱼种表。基础权重为灵鲤 42、银鳞鱼 30、赤纹鲈 17、墨金鲶 8、翠鳍鳊 3，基础售价分别 8/11/20/35/65 鱼券。稀有增益按寻常/少见/稀有/奇珍的权重乘以 `boost^0/0.5/1/1.5` 后归一化，避免高档鱼饵让奇珍鱼变成最常见；渔具面板显示**当前装备条件下**每鱼种概率。水中的装饰鱼不代表这次抛竿结果。
- 品质独立抽样，基础凡/良/珍概率 70%/25%/5%，售出倍率 1/1.5/2.5，向下取整。鱼竿提供稀有增益、珍品概率加成、收线速度和安全张力上限；鱼饵再提供稀有增益、品质加成及咬钩等待缩短。概率与价格常量集中在 `src/game/fishingEconomy.ts`，商城显示实时归一化概率。鱼越稀有，控线难度越高。
- 青竹竿免费，玄铁竿 120、灵木竿 360 鱼券，永久解锁，可切换；素钩无限，香饵 24 鱼券/5 次、月光虫 72 鱼券/5 次。抛竿时锁定本次鱼种、品质和控线参数并消耗一次所选鱼饵，脱钩不退款；余量归零自动退回素钩。不得在一次搏鱼过程中切换渔具改变结算。
- 背包最多 24 尾。钓获成功时只入包一次；满包不能再抛竿。鱼获可锁定，锁定后单卖、批量出售与兑换均不能消耗。配方银鳞鱼 × 2 + 赤纹鲈 × 1 兑换月光虫 × 3，兑换优先取未锁定鱼；无匹配时不改变账本。
- 试营业账本只用版本化 `sessionStorage` 键 `doupo.fishing.trial.v1`；损坏或未知版本重置到默认值，恢复时校验余额、背包、装备和库存。它不与 `engine.ts`、`saveApi.ts` 或生产后端双向同步，也不提供正式奖励。跨标签、跨设备、关闭标签后的持久性**不保证**。未来接正式服务端要定义账户绑定、旧试营业记录不迁移、服务端鱼种/品质抽样、幂等交易和库存迁移，不能上传本地余额兑换真钱或主档资源。

## 实时版本的权威边界（后续阶段）

线上活 `server.js` 与接口 `SPEC.md` 不在仓库，仓库副本是陈旧快照。取得活源码并建立版本化部署前，**不接生产 API，不发奖励**。新增房间服务应与 `EngineHost` 并列，而非把所有人的坐标塞进某个玩家的云档。

1. 已登录账号经 HTTP 取得短期、一次性入场票，连接 WebSocket 后立即认证。服务端解析账号身份；客户端只发 `move(target)`、`reserve(spotId)`、`cast`、`hook`、`tension(held)`、`release` 和社交动作意图，不发坐标完成值、鱼种、概率、奖励或结算结果。未登录者可围观但不能占位或领奖。
2. 房间状态使用 `roomId + epoch + seq`。连接/重连先取全量快照，再按序处理增量；发现缺号或 epoch 变化即重新拉快照。移动路径、速度、可达性和交互距离由服务端验证，客户端只插值显示。一个账号最多持有一个钓位。
3. 钓位从空闲到短时预留，再到角色抵达后占用；预留/占用的竞态在服务端一个原子操作里裁定。超时、离场、换房间、断线宽限到期要释放；短暂重连恢复原座位，旧连接失去操作权。客户端断线时禁用所有会改变结果的操作，不回退本地结算。
4. 钓鱼状态为 `ready → casting → waiting → bite → reeling → caught/escaped`。等待、咬钩窗口和鱼种由服务端生成并持有；服务器时间评判输入、控线和结算，操作带序号/幂等键。鱼获先进入独立的服务器账本，奖励邮件与主档接入前须解决 `/save` 伪档覆盖缺口。
5. 添饵给邻位小幅等待增益；扰水只制造短时假讯或延迟，不能抢位、偷鱼、抹掉已结算鱼获。对同一目标设冷却、保护期、每日次数上限；服务端记账与限频。自由聊天需另有审核、屏蔽、举报，首版仅快捷语和事件播报。

## 验收闸门

- 试营业：鼠标/触屏和键盘在桌面、手机都能走动；点击水面不入水；男女角色四向可切换；占位、离位和一轮钓鱼操作可连续完成。钓获入包后锁定/出售/兑换、购买/装备/扣饵和刷新恢复都能走通；损坏本地记录可恢复默认；无任何主游戏奖励或存档变更。图集透明、八帧顺序正确、场景非空白，切页卸载动画循环。
- 实时阶段：两个真实浏览器争同一位置只有一个成功；双标签同账号不能占两位；断网/重连、后台超时、重启、消息乱序/重放都能回到服务端快照。负对照请求伪造鱼种/奖励不能改变结果。
- 上线阶段：先沙盒与体验服，后按 `design/防作弊开发规范.md` 的部署纪律上线；补齐服务端接口契约、数据迁移/回滚和多房间容量压测。

# 精灵图动画生成规范（试验版）

## 目标与边界

灵田、灵兽苑与钓场优先使用透明精灵图集驱动待机、交互和反馈动画。常规循环以 8 帧为起点，按实际动作调整帧率；模型生成的多帧图不是确定性动画：提示词和参考图能提高身份一致性，但不能保证骨骼、像素级对齐或无缝循环。所有新素材必须经过自动检查和实际播放验收，不能仅凭模型输出入库。

本流程已实测通过的是**根部固定、叶片轻摆的四帧灵草待机**。移动、跳跃、咬钩和复杂动物动作不套用固定根部阈值，需单独定义动作锚点与验收标准。

## 生成流程

1. 先生成单体定稿，裁掉边框和暗角，保留纯白或透明背景。该图成为造型参考，不在后续帧里重设计主体。
2. 用 `gen-image.cjs --reference=...` 一次生成 2×2、阅读顺序的四帧图。提示词明确固定项（配色、叶数、芽点位置、根系、画面比例）与唯一变化项（例如叶尖幅度），写清每帧姿态及回程。
3. 对静止底座的 2×2 RGB PNG 运行 `node sprite-sheet.cjs input.png output/prefix`。输出四张透明帧、透明 `-sheet.png` 图集和 `-report.json`。脚本清理画布最外四像素内覆盖八成边长的直线伪影，不改变主体内部。失败时退出码非零，但仍留下诊断图和报告。
4. 检查报告，再用目标帧率播放至少两个循环。看芽点/五官/肢体是否跳变、背景是否闪烁、循环首尾是否突兀。质检通过只是候选，不等于美术验收。

示例（路径只是示意，命令可以在任意系统的 Node 环境运行）：

```bash
node gen-image.cjs "Use the attached sprite as the exact design. A 2 by 2 sheet of the same plant; fixed roots and bud, only leaf tips sway: rest, left, further left, returning. Equal square cells, plain white background, no gutters or borders, pixel art." --reference=reference.png -o candidate.png
node sprite-sheet.cjs candidate.png output/herb-idle
npm run test:art
```

预览可以用 `ffmpeg -framerate 5 -i output/herb-idle-frame-%d.png -frames:v 4 -plays 0 -f apng output/herb-idle-preview.png`。FFmpeg 只用于预览，不是游戏运行时依赖。运行时应读取透明图集，按帧索引选择 `(列 = index % 2, 行 = floor(index / 2))` 的单元；渲染器用 TypeScript 封装帧率、暂停及低动态偏好。不要把 2×2 图集误当作 1×4 背景位置动画。

## 自动质检

`sprite-sheet.cjs` 要求正方形、可整分的 RGB PNG。以第 1 帧为基准：根部重心横/纵漂移各不超过 8 像素；底部 20% 的不透明轮廓重合度至少 0.8；主体面积保持在基准的 75%–125%；相邻帧变化像素至少达到基准主体面积的 1%。这些是对 512 像素单格的保守异常筛选，**不是通用美术评分**。换分辨率或动作锚点时，应重新标定阈值。

实测四帧灵草：参考图驱动比纯文字四宫格更一致；底部根重心最大横移 2 像素、纵移 2 像素，轮廓重合度 0.884–0.957。模型仍在图底部留下两像素灰线，处理器识别并清除。纯文字版有黑色分格线、叶片角度跳跃，不直接采用。

## 复杂动作策略

- 待机风吹、呼吸和浮动：优先复用一张主体，使用确定性位移/缩放；需要局部形变时再用参考图生成多帧。
- 灵兽行走、喂食、偷取或钓鱼抛竿：先定统一转向、尺度、接地点和关键姿势，按动作分图集生成。四帧不够时增加关键姿势，逐段补中间帧，并逐段验收，不让模型一次猜完整长动作。
- 钓场小鱼摆尾：实测模型参考图四宫格仍出现约 23 像素整体纵向漂移，单靠提示词不合格。先从 AI 定稿中抠出透明主体，再用 `node sprite-tail-rig.cjs source.png output/fish --pivot=155,255 --cut=155` 做 8 帧摆尾；尾尖增加去程/回程的相位形变，八帧画面各不相同。头身逐像素固定，尾鳍最大摆角默认 8°，图集为 4 列×2 行；枢轴和切线必须针对每个素材人工指定并播放验收，尤其检查尾柄接缝。该工具只适用于尾鳍位于左侧的鱼。
- 玩家之间的增益/破坏反馈：主体、工具、粒子和命中特效分层。动作由帧序列驱动，粒子/位移由代码驱动；不把随机特效烘进主体帧导致身份漂移。
- 灵潭角色：参考图生成南/北/东向各八格行走宫格，西向镜像；持竿侧向/背向各生成四个关键姿势，鱼竿和手臂一起入图，不能用曲线绘竿掩盖姿势错误。`sprite-actor-atlas.cjs` 去白、剔除每格不连通的标签与越界碎片，以袍下部/鞋的中心及脚底对齐。生成源图存 `design/sprite-sources/fishing/`，运行时图集存 `src/assets/sprites/fishing/`；执行命令见 README。侧向步态需见前后摆臂、跨步，原地帧不应充当行走循环；背向行走也要观察摆臂和腿部变化。四格钓鱼是单次动作姿势，不声称为八帧循环。
- 正面与背向步态若首轮八格只有换脚、手却基本固定，应重生候选并把“左/右臂交替越过腰前或向身后摆、过渡帧双手回侧边”写进逐帧提示词。男/女正面 `*-walk-swing.png` 和第二轮男/女背向 `*-walk-swing.png` 是接受版；第一轮背向候选手臂仍太固定，未接入。背向因遮挡摆臂不如侧向明显，不能仅靠像素差断言替代目标尺寸播放检查。
- 不合格的帧优先重生候选或手工修整；重试仍不稳定时用部件分层与程序化骨架动画，不宣称模型能保证像素级一致。

工具只处理离线素材，不修改战斗、存档或服务端状态。输入输出路径不硬编码，便于迁移到其他系统和设备。
